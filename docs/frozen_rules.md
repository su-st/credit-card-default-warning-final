## 09 B、C、D與E的核准定義

B、C的原始特徵與M1-NS完全相同（prepare的lag=0、sensitive=False、engineered=False）；額外欄位公式沿用09現有程式：

| 欄位 | 公式 |
|---|---|
| N_CODE0 | sum(PAY_m == 0 for m=1..6) |
| N_CODE_M1 | sum(PAY_m == -1 for m=1..6) |
| N_CODE_M2 | sum(PAY_m == -2 for m=1..6) |
| RUN_CODE0 | longest consecutive run of PAY_m == 0 in PAY_1..PAY_6 order |
| PAYAMT_CHANGE | (PAY_AMT1 - mean(PAY_AMT2..PAY_AMT6)) / (mean(PAY_AMT2..PAY_AMT6) + 1) |
| N_UNDERPAY | sum(PAY_AMTm < BILL_AMT(m+1) for m=1..5) |
| PAYAMT_CV | std(PAY_AMT1..PAY_AMT6, ddof=1) / (mean(PAY_AMT1..PAY_AMT6) + 1) |

### D：共同L1 OOF折內分群建模

群組：近六個月PAY_1～PAY_6任一>0為有延遲，否則無延遲。D使用C的特徵組，與其他候選使用**相同L1五折分配**。每折只取該折訓練客戶，依群組訓練兩個子模型，預測同一折對應群組的驗證客戶，再依客戶ID合併成OOF。不得先分群後另外重切各群五折。
兩模型分數直接合併排序，不另外校準。子模型與分群規則封裝保存以供重載。報告限制：跨群分數尺度未校準，前20%名單可能偏向某一群。

### E：M1-NS的分群門檻政策研究

1. 共用M1-NS模型分數，以其L1 OOF的D2正式成本政策門檻為t0。
2. 有延遲群組固定t0；群組定義同D。
3. 無延遲群組在0.05～0.95、間隔0.01搜尋，只考慮<=t0的候選，不用固定降幅0.05/0.10/0.15。
4. 每候選使用Policy.group與**整體20%名單上限**，以最終名單計算D2成本。總成本最低者勝，同成本選較高無延遲群組門檻。
5. 同時列出截取前／後結果；若上限觸發使最終名單不變照實報告，不為改善數字改規則。
6. E不產生新模型分數，不參加G2b模型替換排序，不直接套到平台正式名單；仍須完成研究比較。

## D2成本情境與四軸敏感度

主要scenario：max_list_rate=0.2、loss_ratio=0.5、contact_cost=50、rescue_rate=0.2。
cost_sensitivity：max_list_rate=[0.1,0.2,0.3]、loss_ratio=[0.5,0.75,1.0]、contact_cost=[50,500,2000]、rescue_rate=[0.1,0.2,0.3]；C3以笛卡兒積列出81情境。
損失_i=max(9月帳單_i,0)×loss_ratio（bill_at(df,0)）。總成本=FN損失加總+TP損失×(1-rescue_rate)加總+最終名單人數×contact_cost。
choose_threshold在0.05～0.95、間隔0.01的91點，先套Policy.single與上限再算成本；同成本取較高門檻。每候選都可截取，不存在超額而無解。
每批名單上限floor(rate×人數)，完整精度分數降冪、同分ID升冪；保留原始／最終名單、上限觸發，情境與政策識別分開。同列上限下Recall/F1、無上限成本及F1參考。
50%只是參考監理參數下限的情境起始假設，非實際損失率；帳單非EAD。情境結果不稱銀行實務最佳政策。提前預警F5只比較AUC與固定比例涵蓋率，不套成本門檻。

## 期末既有02平均損失算法

這是**期末既有02平均損失算法**，不是期中算法；期中門檻為F1選出的0.58。原公式與選擇規則保持不變。

| legacy_threshold_analysis欄位 | 核准值 |
|---|---|
| loss_per_default | None（JSON null），同一L1違約者9月帳單負值歸零後平均，不乘loss_ratio |
| cost_per_contact | 50 |
| rescue_rate | 0.2 |
| rule | cost |
| max_list_rate | None（JSON null，無名單上限） |
| top_n_rate | 0.2 |
| sensitivity_contact_costs | [50,500,2000] |
| sensitivity_rescue_rates | [0.1,0.2,0.3] |

敏感度只變動上述聯絡成本、挽回比例**兩軸**，不是D2四軸。
原成本=FN人數×平均損失+TP人數×平均損失×(1-挽回比例)+(TP+FP)×聯絡成本；原GRID升冪及idxmin選擇規則保留，所以同成本取較低門檻。
與D2「無上限成本對照」比較。報告限制：同時差在平均／逐客戶、全額／乘0.5、同成本舊算法低門檻／D2高門檻，只能作兩種成本算法整體比較，不能分別估計各因素影響。由蘇韻蓉執行與確認，本次不跑02。

## G2b條件、D7與多候選排序

基準M1-NS；候選也不含敏感屬性。含／不含敏感屬性只在RQ1比較，不作替換依據。所有候選L1 OOF同客戶同折，兩方都用Policy.top_n(0.2)，不是共同數值門檻。
同時達到三條件才可替換：前20%名單Recall相對基準提升>=0.01；AUC不低於基準；性別、年齡層EO差距增加各<=0.02。EO在同一份前20%名單上計算。
排序候選**只包含05、09 B、09 C、09 D**。多個候選同時達標，以未四捨五入的原始值依序比較：

1. 相對M1-NS前20%名單Recall提升最多。
2. 性別／年齡層兩個EO增加量的最大值最小。
3. 兩個EO增加量合計最小。
4. One-Hot展開前的原始輸入特徵數較少。
5. 固定順序05、09 B、09 C、09 D取前者。

這是事前訂定的多目標工程決策，不是統計檢定；EO容許值不表示符合公平性。無候選達標則保留M1-NS基準。
各方法仍另列共同0.5無上限、固定前20%、各自正式政策三種比較。G2b依規格4.5.1建立模型＋政策清單，同模型不同政策共用model_hash，policy_id不同；正式門檻只由各自L1 OOF產生。

## D8與族群門檻

Recall分母（違約人數）或FPR分母（未違約人數）少於93人標小樣本；93本身不標。列總人數、違約、未違約人數與Wilson score 95%區間，分母0為空值並標無法計算，不填0。
族群差距bootstrap以客戶為單位、族群×標籤分層，2000次、seed42、percentile 2.5/97.5%；有效重抽少於1900次不提供可靠區間。兩模型差異用成對重抽。
族群門檻只作研究模擬不用平台（D5）；性別、年齡層、性別×年齡層分別執行，每次互斥且完整。
`group_threshold.target_definition=single_policy_oof_recall`：以同模型、同次訓練OOF的主要成本政策單一門檻t0，取**原始名單(score>=t0，截取上限前)**整體Recall作目標，不固定一個Recall數值，不用測試集調整。
各群在0.05～0.95、間隔0.01搜尋，取OOF Recall與目標Recall絕對差最小者；差距先四捨五入到4位小數，仍相同取較高門檻。不是Hardt方法的完整實作。
族群政策最終名單上限20%；觸發後不保證各群Recall仍接近目標，原始／最終結果都保留。
