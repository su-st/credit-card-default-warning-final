### T-張3 06 族群公平性（F3）

- **分類**：需依新規格修改
- **可以開始的時間**：C1、C2 合併後
- **分支名稱**：`exp/fairness-groups`
- **目標**：比較含與不含敏感屬性的模型（M1 與 M1-NS），在各族群的漏判率、誤報率與差距
- **要改的檔案**：`experiments/06_fairness_groups.py`
- **不能改的檔案**：`src/` 底下的共用模組、其他組員的實驗檔。需要共用模組新增功能時告訴組長
- **資料與模型**：L1。M1 用 `prepare(..., sensitive=True, ...)`，M1-NS 用 `sensitive=False`
- **怎麼做**：
  1. 分組：性別、年齡層、性別×年齡層、教育程度、婚姻狀況
  2. 兩個模型都做三種比較並分開呈現：共同數值門檻 0.5（對照期中）、固定名單人數前 20%、各自的正式政策
  3. 用 `evaluate` 的 groups 參數取得各族群的總人數、違約人數、未違約人數、Recall、FNR、FPR 與 Wilson 信賴區間。分母為 0 時是空值，不是 0
  4. 族群差距（EO 差距＝各族群 Recall 的最大差距、FPR 差距）用 `gap_ci` 算 bootstrap 信賴區間，每次只給一種分組。比較兩個模型的差距變化時用 `pred_b` 做成對比較
  5. 違約人數或未違約人數少於 93 人的族群標示小樣本
- **輸出**：`results/<run_id>/fairness_groups.csv`、`fairness_gaps.csv`（含信賴區間）、圖
- **驗收標準**：
  - 門檻不寫死在程式裡，由政策物件決定
  - 三種比較分開列出並標明名稱
  - 每個族群都有三種人數與區間
  - 小樣本有標示
- **報告要寫的內容**：RQ1 的方法與結果、區間的解讀、小樣本的限制，並說明「差距縮小不代表符合公平性要求」

### T-張4 07 族群門檻（F3b）

- **分類**：需依新規格修改
- **可以開始的時間**：C1、C2 合併後
- **分支名稱**：`exp/group-threshold`
- **目標**：參考 Hardt et al.（2016）的簡化做法，各族群用自己的門檻讓 Recall 接近，觀察對整體表現與名單的影響
- **要改的檔案**：`experiments/07_group_threshold.py`
- **不能改的檔案**：`src/` 底下的共用模組、其他組員的實驗檔。需要共用模組新增功能時告訴組長
- **資料與模型**：L1，以 M1-NS 的 OOF 分數為基礎。族群門檻只是研究比較，不用在平台名單
- **怎麼做**：
  1. 目前 07 用的單一門檻來自另一個模型，要改成在 M1-NS 自己的 OOF 上用 `choose_threshold` 選出
  2. 性別、年齡層、性別×年齡層三種分組分別執行，每次只用一種分組，每位客戶只對應一個門檻
  3. 族群門檻用 `Policy.group(分組名稱, 各族群門檻, 名單上限)` 表示，再用 `apply_policy(score, policy, partition=...)` 產生名單
  4. `apply_policy` 回傳的原始名單與最終名單都要保留。名單上限觸發時要註明：各族群 Recall 接近的設計在截取後不保證成立，實際數字以最終名單為準
  5. 與單一門檻比較整體 Recall、誤報人數、名單人數、EO 差距與區間
- **輸出**：`results/<run_id>/group_threshold_<分組>.csv`、長條圖
- **驗收標準**：
  - 單一門檻與族群門檻來自同一個模型
  - 三種分組分開執行
  - 有保留原始名單與最終名單的結果
  - 報告寫成「參考 Hardt et al. 的簡化做法」，不寫成完整實作
- **報告要寫的內容**：方法、結果、交叉族群小樣本的保守解讀，以及用敏感屬性決定門檻的合規疑慮


## 全組共同規則

1. **資料分層**。11/28 模型凍結前，只能用訓練集：
   - L1：`dev_data()` 回傳的 24,000 筆訓練集，所有實驗與選擇都在這裡做（用 OOF 預測）
   - L1-H：`dev_holdout()`，平台開發與 TAIDE 測試用，不能拿來選模型，也不寫進報告
   - L2、L3（測試集與 10 個 seed）：11/28 之後由 Codex 用你合併的程式執行，你不需要也不可以自己跑
2. **不要看測試集**。凍結前不產生、不查看任何測試集的預測或指標，也不要打開電腦裡舊的 `outputs/predictions.csv`。
3. **用共用模組**。讀資料、特徵、模型、門檻、評估一律用 `src/protocol.py`，不要自己切分資料或自己寫指標。
4. **特徵參數要寫明**。`prepare(df, lag=..., sensitive=..., engineered=...)` 三個參數都沒有預設值。平台基準模型是「不含敏感屬性」。
5. **三種比較分開呈現**（規格第 4.5.4 節）：
   - 共同數值門檻：`Policy.single(0.5, None)`，對照期中
   - 固定名單人數：`Policy.top_n(0.2)`，看排序能力
   - 正式政策：`choose_threshold(...)` 選出的門檻加名單上限 20%
6. **族群結果**要列出總人數、違約人數、未違約人數與 Wilson 信賴區間。違約人數或未違約人數少於 93 人時標示小樣本，解讀以區間為準。
7. **用詞**。分數叫「風險分數」，不叫違約機率。SHAP 因素是「模型判斷依據」，不是違約原因。繳款代碼 0 與 −2 的意思官方沒有定義，不要寫成事實。
8. **結果輸出**用 `start_run(...)` 與 `run.save_csv()`、`run.save_fig()`，會存到 `results/<run_id>/`。報告的表和圖都要附 run_id。
9. **程式要能指定資料層級**。主要流程寫成函式，資料由參數傳入，你在 L1 上開發與測試，凍結後 Codex 會用同一份程式跑 L2、L3。
10. **AI 工具**。可以使用，但要在 PR 說明寫出用了什麼工具、做了什麼，報告附錄 B 也會列出。
11. **不要上傳** `.env`、`outputs/`、模型檔。

```python
from src.protocol import (dev_data, dev_holdout, prepare, make_model, oof_predict,
                          cv_evaluate, tune_model, load_rules, Policy, apply_policy,
                          choose_threshold, coverage_curve, evaluate, gap_ci,
                          bill_at, start_run)

df = dev_data()                                   # 24,000 筆訓練集，含 default 欄

out["overall"]
out["groups"]
out["gaps"]

run = start_run("L1", "說明這次在做什麼", model_id="xgb-tuned-ns-s42train")

```
