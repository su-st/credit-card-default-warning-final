## 閱讀前說明

1. **本表是對照，不是合規聲明。** 指引屬行政指導性質，不具拘束力，適用對象是金融機構；本專題是課程研究原型，沒有實際對客戶提供服務，也沒有串接真實銀行系統（規格 §6.1）。表中不使用「符合法規」的說法。
2. 「本專題做法」只寫專案規格與文件已有的內容。**規格已訂定、但程式尚未完成或尚未確認的項目，不標「已做到」**，標「部分」或「待補」。
3. **本表不包含任何測試集指標。** 公平性欄位記錄 L1 與 L2 正式結果的 run_id、關鍵結論與實驗脈絡（L2 正式結果於模型凍結 `g2b-20261122` 後執行，平台已切換至 L2 正式結果 PR #57）。
4. 用詞：分數叫「風險分數」，不叫違約機率；SHAP 因素是「模型判斷依據」，不是違約原因；繳款代碼 0 與 −2 的意思官方沒有定義，不寫成事實。

**現況圖例**：

| 標示 | 意思 |
|---|---|
| 已做到 | 專案內已有對應的做法或紀錄 |
| 部分 | 只做到一部分，或規格已訂但程式尚未完成，備註說明 |
| 未做到 | 沒有做，備註說明原因 |
| 待補 | 要等實驗結果或平台定稿才能填 |
| 不適用 | 課程原型情境下不適用，備註說明 |

## 一、風險自評（總則 三）

指引說明運用 AI 系統的風險高低由金融機構綜合考量下列因素後自行判斷，下表是本專題的自評，不是指引對本專題的判定。

| 因素 | 本專題情況 | 自評 |
|---|---|---|
| (一) 是否面對客戶、對權益有重大影響 | 產出違約預警名單與關懷訊息草稿；指引以信用評分為較高風險之例，本專題屬違約預警，以較高風險看待 | 偏高 |
| (二) 使用個人資料的程度 | UCI 公開資料集（CC BY 4.0），含性別、年齡、教育、婚姻等個人屬性；平台使用歷史資料與模擬帳號 | 中 |
| (三) AI 自主決策程度 | 模型只產生名單與訊息草稿；客戶訊息發送前須行員確認；名單上限主要設定為 20%（D2） | 較低 |
| (四) 系統複雜性 | XGBoost 搭配 SHAP；另保留邏輯迴歸與決策樹作為可解釋基準 | 中 |
| (五) 影響利害關係人的程度與廣度 | 原型只發到測試帳號（11/23 LINE 實測亦僅送達測試收件者）；若實際部署則會升高 | 低（僅限原型） |
| (六) 救濟選項的完整程度 | 尚未設計申訴或更正管道 | 不足 |

指引說明高風險系統宜有較完整的記錄、較高頻率的監控、較嚴格的審查核准，必要時由第三方稽核。本專題的對應見下表第一章。
